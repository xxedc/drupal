## 1. 概览

### 1.1 整体评分：D

基础抓取（HTTPS、404、robots、canonical、分页链接、缓存聚合、HTTP/2/3）大体可用，但存在多项直接影响抓取与收录的高危问题：sitemap 完全缺失、站内筛选参数触发 500、品牌/域名不统一、详情页元数据与结构化数据缺失。当前状态不建议直接大规模提交搜索引擎。

### 1.2 最严重的 5 个问题

1. **sitemap.xml 返回 404，robots.txt 也未声明 Sitemap**：`simple_sitemap` 已启用但 `simple_sitemap` 表 0 行，`/sitemap.xml` 404。
2. **`/articles?cat=<非法值>` 返回 500**：无效筛选参数直接触发服务器错误，会产生大量抓取错误。
3. **品牌与域名不统一**：页头 `dclili`、页脚 `XEDC`、站点名 `DClili`、首页 title `XEDC`、`og:site_name` 为全角 `ＸＥＤＣ`；`og:url` 硬编码 `https://gitxx.xyz`，而任务域名为 `tlte.top`。
4. **详情页缺少 meta description 与 Open Graph/Twitter Card**：文章 57 有非空 `field_summary` 且页面已输出摘要，但 HTML 无 `meta description`；所有详情页无 `og:*`/`twitter:*`。
5. **全站没有 JSON-LD 结构化数据**：无 `WebSite`/`SearchAction`/`Organization`/`ImageObject`/`Article`/`VideoObject`/`BreadcrumbList`。

### 1.3 最容易见效的 5 个改动

1. 生成 sitemap，并在 `robots.txt` 增加 `Sitemap: https://<正式域名>/sitemap.xml`。
2. 对 `/articles` 的 `cat` 参数做整数/术语校验，非法值返回 404 而不是 500。
3. 把 node 的 metatag description 从 `[node:summary]` 改为 `[node:field_summary]`，并为详情页补 `og:image`（取封面/首图）和 `twitter:card`。
4. 先补 `Organization` + `WebSite`（含 SearchAction）+ `Article`/`ImageObject` + `BreadcrumbList` 四类 JSON-LD。
5. 删除详情页模板中的重复 H1（保留一个），并给首页补 H1；同时为 article/video/page 增加 pathauto 别名。

## 4. 建议的修复顺序

### 第一批：立刻做（上线/本轮修复）

1. **P01 sitemap**：先排除测试/空页，生成 sitemap，确认 200 + `application/xml`，再加 robots `Sitemap:`。
   - 预期收益：所有引擎可发现 URL，收录速度显著提升。
   - 风险：若不过滤测试/薄页，会把低质页面一起提交；建议先配置 bundle/术语排除。
2. **P02 500**：修复 `/articles?cat=` 非法值。
   - 预期收益：消除 5xx 抓取错误，避免垃圾参数打挂页面。
   - 风险：改动 views/预处理，需要回归筛选、分页、缓存。
3. **P03 品牌/域名**：先确定唯一品牌名和唯一正式域名，再统一配置与模板。
   - 预期收益：canonical/分享/实体信号一致，避免域名分裂。
   - 风险：域名迁移涉及 301、Cloudflare、外部链接；必须一次性规划，避免反复切换。
4. **P04 详情页元数据**：补 description + OG/Twitter/og:image。
   - 预期收益：搜索结果摘要与社交分享立即改善。
   - 风险：token 需按 bundle 验证；图片需绝对 URL 和合适尺寸。
5. **P09 noindex 缺口**：`/search`、登录/注册补 noindex 或屏蔽。
   - 预期收益：减少低质量页面进入索引。
   - 风险：若未来需要登录页收录，需调整策略。

### 第二批：本周

1. **P05 JSON-LD**：Organization/WebSite/SearchAction/Article/ImageObject/VideoObject/BreadcrumbList。
   - 预期收益：富结果/知识面板/图片视频展现机会。
   - 风险：结构化数据必须与可见内容一致，错误标记可能触发人工处理。
2. **P06 H1**：去重复、补首页 H1。
   - 预期收益：主题语义清晰，模板更规范。
   - 风险：低；需检查 CSS 对 `.page-title` 的依赖。
3. **P07 URL/标题**：article/video/page pathauto；模特标题唯一化。
   - 预期收益：URL 语义化、标题可区分。
   - 风险：新增别名后需为旧 `/node/ID` 保留 301；批量生成需测试。
4. **P08 分页 canonical**：保留 `?page=N` 自引用。
   - 预期收益：分页内容可独立收录。
   - 风险：需确认筛选参数仍被 canonical 去重。
5. **P11 www 301 + P15 HSTS**。
   - 预期收益：主机名归一、传输安全。
   - 风险：Cloudflare/Nginx 规则变更需先在测试环境确认，避免误跳转。
6. **P12 图片 LCP/srcset/宽高**。
   - 预期收益：LCP/CLS 改善，图片搜索更好。
   - 风险：需真实浏览器复测，避免首图 eager 造成带宽竞争。

### 第三批：以后

1. **P10 内容清理**：测试/乱码节点取消发布或删除；薄标签/模特页补内容或 noindex。
   - 预期收益：站点整体质量提升。
   - 风险：删除内容不可逆，需先备份/确认 URL 301。
2. **P13 多引擎**：修复 sitemap 后提交 Bing/Yandex/百度/Naver/Seznam；确认 IndexNow key。
   - 预期收益：非 Google 引擎收录。
   - 风险：各平台验证方式不同；IndexNow 密钥不可泄露。
3. **P14 分类拼写**：合并 `cospaly`/`cosplay`，处理旧 URL。
   - 预期收益：消除重复分类与拼写错误。
   - 风险：涉及内容归类与 301，需人工确认。
4. **P16-P22 低优先级**：404 canonical、重复面包屑、favicon/manifest、slogan、og locale、302→301、标题层级。
   - 预期收益：细节完善。
   - 风险：低。

   - 预期收益：从“静态判断”升级为“数据驱动”。
   - 风险：需要外部平台权限与时间窗口。
