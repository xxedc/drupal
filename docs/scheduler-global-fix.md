# DcLili 定时发布全局修复

`publish_on` 存 Unix 时间戳，cron 用当前时间比较。网站时区是 `Asia/Shanghai`。编辑框已固定使用网站时区。

## 发现的问题

1. **审核状态和发布状态不一致。** 设置了未来的 `publish_on` 时，Scheduler 会把当前译文标成未发布，但审核状态可以仍是「已发布」。后台因此看起来像已经发布。员工编辑表单还会把草稿的审核控件默认改回「已发布」，下一次保存又变回去。
2. **译文提前发布。** `status` 和 `publish_on` 按语言分开存。原文未发布时，英文、日文、俄文可以已经是已发布，并且带着更早的 `publish_on`。自动翻译在审核状态为「已发布」时就会生成译文，不看节点是不是真的已发布。
3. **cron 只处理到期的那一种语言。** 查询能查到节点，但循环里跳过尚未到期的中文，只处理已到期的译文。所以未发布的中文在 `drush scheduler:cron` 之后仍然不发布。
4. **已撤下不能定时发布。** 审核流里没有从「已撤下」转到「已发布」的转换，到点会记失败日志并保持原状。

节点 143 的中文发布时间是 2026-10-31 01:52（上海），译文仍停在 01:05 且已发布。136、137 的中文分别是 11 月 1 日 00:26 和 00:36，译文是当天 08:26 和 08:36 且已发布。这些中文时间都还没到，cron 不会发布它们。

## 修复方式

- 未来的定时发布在保存末尾生效：全部译文改为未发布，`publish_on` 与原文对齐。审核状态若是「已发布」，改回工作流默认的草稿。
- 原文仍在等待时，cron 不再单独发布译文。原文到期后，所有译文一起改为已发布并清空 `publish_on`。有审核的内容同时转到「已发布」。
- 已安排未来时间的草稿，编辑表单不再把审核控件强制改成「已发布」。
- 自动翻译只处理审核状态为「已发布」且节点确实已发布的内容，避免定时等待期间生成已发布译文。

已把 136、137、143 按原文时间重新对齐，译文改为未发布，审核状态为草稿。

## 验证结果

- `php -l` 通过，已执行 `drush cr`。
- 以管理员身份打开 136 的编辑表单：审核值保持草稿，没有被改成已发布。
- 新建美图，审核设为已发布，并带一条已发布的英文译文。保存后审核为草稿，中文和英文都未发布，时间都是原文的未来时间。
- 把该美图和一篇基本页面的原文时间改成已过期后执行 `drush scheduler:cron`：两种内容的全部语言都变为已发布，`publish_on` 已清空，美图审核状态为已发布。
- 同一次 cron 没有发布仍在等待的 136 和 143。
- 测试节点已删除。
